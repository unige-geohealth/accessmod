# Module 7 Implementation Plan: Best Coverage Selection

## 1. Objective

The goal is to implement the "Best Coverage Selection" module (Module 7). This module selects a specified number of health facilities that provide the best overall population coverage.

## 2. Core Workflow

The module's primary input is a **pre-computed catchment vector layer**. This layer must be generated by the user beforehand, typically by running the **Module 3 (Geographic Coverage)** analysis. This workflow ensures that the complex travel time parameters (anisotropic, knight's move, etc.) are handled by the dedicated module, leaving Module 7 to focus solely on the selection algorithm.

The user workflow is as follows:
1.  Run **Module 3** to generate a catchment layer (`vCatchment`).
2.  Run **Module 7**, using the `vCatchment` layer from step 1 as the main input, along with a population layer.

## 3. Handling Catchment Data

A key technical detail is how AccessMod handles the `vCatchment` data. Unlike most other spatial layers, catchments are not stored as native GRASS layers. This is because individual catchment polygons often overlap, which would violate GRASS's topological rules (features in the same layer cannot overlap).

Instead, catchments are stored as standard **shapefiles** within the project's `accessmodShapes` directory. The user interface populates a dropdown list with the available `vCatchment` keys. When a user selects a catchment, the application uses a helper function like `amGetShapesList(<id>)` to resolve the key into a list of file paths for the corresponding shapefile components (.shp, .shx, .dbf, etc.).

The implementation of Module 7 must therefore read the input catchment data directly from these shapefiles using its key, rather than attempting to access it as a GRASS layer.

### Step 2: Refactor the Core Logic

**File:** `tools/R/amAnalysisBestCoverage.R`

**Actions:**
- The function signature must be updated to accept `inputCatchment` as its primary data source.
- The function body will be a straightforward implementation of the selection algorithm from the prototype. It will:
  1. Read the `inputCatchment` vector and `inputPopulation` raster.
  2. Calculate the population within each catchment polygon.
  3. Iteratively select the catchment that covers the most *remaining* population, remove its geometry from overlapping catchments, and recalculate their populations until the desired number of facilities is selected.
- **Note:** The core logic will be adapted from the `hf_best_cov` function found in the prototype script `new_module_7_plan/4_adapted_hf_best_cov_function.R`.
